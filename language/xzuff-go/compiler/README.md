# Xzuff Go compiler — first native executable milestone

This is an early, deliberately limited C++20 compiler implementation. It is not a complete Xzuff Go compiler.

## Supported source subset

The compiler accepts one function with an integer return constant:

```xgo
function main() returns i32 {
    return 42;
}
```

The return constant must fit the signed 12-bit immediate range (-2048 through 2047). The lexer handles identifiers, decimal integer literals, punctuation, whitespace and `//` comments. The parser rejects unsupported statements and extra tokens.

## Output

The compiler now writes a minimal ELF64 little-endian RISC-V executable, rather than an 8-byte raw code fragment. Its entry code contains three real RV64 instructions:

1. `addi a0, zero, value` — set the process exit status.
2. `addi a7, zero, 93` — select the Linux RISC-V exit syscall.
3. `ecall` — request process exit from the Linux kernel.

The ELF contains a 64-bit ELF header, one loadable program header, a load segment and an entry address. The target is **Linux RISC-V user space**, not the custom Gravity Kernel ABI. It is not yet an OpenXzuff `.xexe` and cannot be assumed to boot or run on Gravity Kernel.

## Build and test

With CMake 3.20+ and a C++20 compiler:

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel 2
ctest --test-dir build --output-on-failure
./build/xzuff-go language/xzuff-go/tests/return_42.xgo build/return_42.elf
file build/return_42.elf
```

On Windows, use the executable path generated by the selected CMake generator.

The built-in self-test checks the exact RV64 instruction bytes for return values 0 and 42. CI also checks that the generated ELF is larger than its 4 KiB code offset.

## Not implemented yet

- General expressions, variables, calls with arguments, multiple functions and modules.
- Full grammar, AST, semantic/type checking and reliable diagnostics for the whole language.
- Branches, loops, strings, records, generics, memory safety, async and GUI DSL.
- ELF sections/symbols/relocations and a general linker.
- OpenXzuff-specific executable format and Gravity Kernel loader integration.
- Standard library, syscall ABI, runtime and target emulator/hardware integration.
- Broad positive/negative compiler conformance suite.

Treat this as a real but narrow native-code milestone. Do not advertise the compiler as 100% complete until the language specification, compiler, executable ABI and tests are complete.
